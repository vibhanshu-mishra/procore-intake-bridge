# Procore Intake Bridge v0.1.0

Procore Intake Bridge v0.1.0 is the first public source release of an independent, local-first,
read-only workspace for reviewing Procore intake without writing back to Procore.

## Highlights

- Local-first intake workspace for RFI and Submittal records.
- Demo Mode with deterministic synthetic data in local SQLite and no Procore credentials.
- Product Dashboard and Intake Review Workspace for local review and navigation.
- Local lifecycle status and history plus a read-only Operator Triage Queue.
- Metadata-only attachment manifest review without attachment content processing.
- Sanitized JSON, Markdown, and CSV summaries generated by local commands.
- API route reference and local OpenAPI documentation.
- DMSA connection-profile boundaries with PyProcore as the guarded read boundary.
- Polling and webhook event-queue foundations for separately reviewed private use.
- Readiness, diagnostics, safety, and maintainer-review tooling for local evaluation and review.

## Quick start

Run the canonical Demo path from a clean checkout:

```bash
git clone https://github.com/vibhanshu-mishra/procore-intake-bridge.git
cd procore-intake-bridge

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"

make first-run
make demo-seed
make start
uvicorn app.main:app --reload
```

Then open the local Product Dashboard, Intake Review Workspace, or [local OpenAPI docs](http://localhost:8000/docs).
Demo Mode uses synthetic records and local SQLite; it requires no Procore credentials, cloud
service, or external database. Use `make demo-reset CONFIRM="RESET DEMO DATA"` only to reset
deterministic Demo-marked records.

## Safety boundaries

- No Procore write-back routes.
- No live Procore calls by default.
- Attachment review is metadata-only.
- Local lifecycle status does not update Procore.
- Private Sandbox, Pilot, and Hosted use remains separately gated and reviewed.
- Real credentials, customer data, private URLs, identifiers, reports, and generated operational
  output remain outside the public repository.
- This release makes no production, compliance, security-certification, or Procore approval claim.

## Known limitations

- No notifications or alerting system.
- No full immutable audit-log implementation.
- No automatic retention enforcement.
- No application-level encryption-at-rest implementation.
- Hosted deployment remains planning and preparation, not a deployed service.
- Private security, legal, infrastructure, privacy, and operational review remains required before
  live use.
