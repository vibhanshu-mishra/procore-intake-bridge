# Release Candidate Checklist

J8 consumes this checklist as evidence only. Prepared `0.1.0` is release metadata, not a release;
J8 performs no build, publish, upload, tag, release, docs deployment, application deployment, or
workflow change. A maintainer must authorize any later release, and no production, Pilot, hosted,
legal, privacy, security, release, or deployment approval is implied.

Prepared target: `0.1.0` release-candidate metadata; not released.

- [ ] J6 canonical version source, package metadata, changelog, and release boundary agree.
- [ ] J5 documentation navigation and local-only preview checks pass.
- [ ] J4 hosted UI candidates retain protection and private-review gates.
- [ ] J3 documents every route and its protection/method boundary.
- [ ] J2 fake local Demo seed/reset remains isolated and deterministic.
- [ ] J1 local setup and troubleshooting guidance remains usable.
- [ ] I8/I9 security readiness and gap closeout honestly retain private-review requirements.
- [ ] H1/H2 public repository readiness and E4 release-readiness inputs remain current.
- [ ] Public safety, route, usability, docs-site, quality, changelog, and roadmap checks pass.
- [ ] Generated outputs remain ignored and no private value is committed.
- [ ] No package/Docker build, publish, upload, tag, release, deployment, or workflow change occurred.
- [ ] A maintainer performs later release-candidate review and explicit authorization.

Checking these public items does not mean a release happened or was approved. Production, Pilot,
release, deployment, publication, compliance, certification, and Procore approval are not granted.
