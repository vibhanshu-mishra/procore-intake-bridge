# Security policy

Do not report real secrets or private customer data in a public issue. Never paste access tokens,
refresh tokens, client secrets, webhook secrets, admin tokens, App Version Keys, Authorization
headers, signed URLs, private logs, company/project identifiers, or payloads.

If a credential may have been exposed, rotate or revoke it immediately with the owning provider;
deleting a post is not sufficient remediation.

Private reporting contact: **SECURITY_CONTACT_PLACEHOLDER**. Until a real private channel is
published, do not transmit sensitive details—send only a request for a secure reporting channel.
Use synthetic reproduction data. No bug bounty exists unless explicitly announced in writing.

The project is not production-secure and provides no production security guarantee.
